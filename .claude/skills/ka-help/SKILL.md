사용자는 개발자가 아니다. 아래를 그대로 읽어 주지 말고 질문에 맞는 부분만 짧고 쉽게 답한다. 자세한 안내가 필요하면 `docs/claude-code-guide.md`를 읽고 그 절만 옮긴다.

## 하루 흐름 (이 순서면 된다)
1. **말한다** — "지도 위 글자가 잘려요"처럼 보이는 증상을 그대로 말한다(스크린샷 첨부 가능).
2. **Claude 가 고친다** — 짧은 계획을 적고 바로 고친다. 큰 변경은 "계획 먼저"라고 하면 계획을 보여 주고 기다린다.
3. **검증한다** — `/ka-check` (C++ 를 고쳤다면 필수. 안 하면 Stop 훅이 알려 준다).
4. **눈으로 확인한다** — `/ka-run` 으로 앱을 열고 Claude 가 알려 준 "확인할 한 가지"만 본다.
5. **저장한다** — 마음에 들면 `/ka-save` (커밋). 푸시는 따로 말할 때만 한다.

## 명령
| 명령 | 언제 |
|---|---|
| `/ka-status` | 지금 어디까지 왔는지 한눈에 |
| `/ka-doctor` | 빌드·도구가 준비됐는지 점검, 없으면 설치 방법 |
| `/ka-work <할 일>` | 새 작업 시작(계획 → 수정 → 검증까지 한 번에) |
| `/ka-check` | C++ 수정 뒤 검증(Graft·clangd·Archify·시험) |
| `/ka-run` | 만든 앱 열기(이미 실행 중이면 그대로 둔다) |
| `/ka-save` | 바꾼 파일을 골라 저장(커밋) |
| `/ka-undo` | 방금 한 수정 되돌리기(안전한 방법으로) |
| `/개발설정` | Claude Code 전역+프로젝트 개발설정 적용·점검 |

## 알아 두면 좋은 것
- 화면 아래 줄에 모델·컨텍스트 사용량·브랜치·검증 대기가 보인다.
- 권한 창이 나오면 영어를 다 읽을 필요 없이 Claude 가 한국어로 설명한 내용을 확인하고 "예/아니오"만 고른다. 잘 모르겠으면 "아니오" 후 Claude 에게 이유를 물어본다.
- 실수로 고친 것은 `/ka-undo`. 세션 안에서 방금 한 편집은 `/rewind` 로도 되돌릴 수 있다.
- 노력 수준은 기본 `high`(정확 우선). 빠르게 하고 싶으면 `/effort medium`.
