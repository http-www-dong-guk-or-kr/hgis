작업: $ARGUMENTS

AGENTS.md·CLAUDE.md 규칙을 그대로 따른다. 이 스킬은 순서만 정한다.

1. **이해** — 증상·목표를 한 문장으로 다시 쓴다. 지도·CRS·WMS·디지타이즈·정합·조판·내보내기·레이어 순서 문제면 고치기 전에 프로젝트/레이어 CRS, 변환, 캔버스 레이어 순서, 축척, provider URI 를 직접 확인한다(사용자에게 진단을 시키지 않는다). 사용자 화면 확인이 필요한 변경은 `ka-hgis-verify` 스킬을 함께 쓴다.
2. **짧은 계획** — 증상/목표 · 추정 원인 · 손댈 파일 · 사용자가 볼 완료 조건. 사용자가 "계획 먼저"라고 했으면 여기서 멈추고 확인을 받는다. 아니면 바로 진행한다.
3. **위치 찾기** — 관련 스킬(`ka-hgis-gis`의 task-map, 조판·정합·유적번호면 `ka-hgis-sheet`, 주변유적 받기면 `heritage-intranet`)을 먼저 본다. Graft(`mcp__hgis_graft__graft_find_code`/`graft_file_api`)로 후보를 좁히고 시그니처·줄은 소스로 확인한다. 전체 텍스트·Qt 시그널/슬롯 연결은 Grep 으로 본다. 큰 파일은 함수 위치를 찾은 뒤 범위만 읽는다.
4. **최소 수정** — 기존 패턴·헬퍼를 쓰고 drive-by 리팩터·새 의존성은 하지 않는다. 함수를 옮기거나 이름을 바꾸면 소스 텍스트를 읽는 시험(`.claude/rules/tests.md`)을 먼저 확인한다. 관련 없는 미커밋 작업은 건드리지 않는다.
5. **검증** — C++ 를 고쳤다면 `/ka-check` 절차를 실제로 수행한다. 문서·설정만 고쳤다면 diff·텍스트 검사로 확인한다.
6. **기록** — `.codex/NOW.md` 맨 위에 `## <날짜> <제목>` 항목을 추가한다: 무엇을 했나, 증거(Graft 함수·줄, clangd 줄:열→줄, ctest 이름+초, Archify 이름+9/9, smoke 결과), 커밋·푸시 여부. 제품 현황이 바뀌었으면 `docs/HANDOFF.md`(정본)에 한 줄. 사용자가 보는 UI 용어를 임의로 바꾸지 않는다.
7. **보고** — 결론 먼저, 실제로 돌린 명령과 결과, **사용자가 눈으로 확인할 것 한 가지**(필요하면 `/ka-run`). 확인하지 못한 것은 "확인하지 못했다"고 쓴다. 저장(커밋)은 사용자가 `/ka-save` 라고 말할 때만.
