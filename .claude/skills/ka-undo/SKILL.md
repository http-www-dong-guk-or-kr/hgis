되돌릴 것: $ARGUMENTS

먼저 현재 상태를 보여 준다: `git status --short`, `git log -5 --oneline`. 그다음 상황에 맞는 **가장 약한** 방법을 고른다.

1. **이 세션에서 방금 한 수정(아직 저장 안 함)** — Claude Code 의 `/rewind` 를 안내한다(사용자가 직접 실행: 편집 지점을 골라 코드 되돌리기). 세션 밖에서 바뀐 것은 되돌리지 못한다.
2. **저장하지 않은 특정 파일 하나** — 사용자가 파일을 확인해 준 경우에만 `git restore -- <경로>` (권한 창이 뜬다). 그 파일의 변경 내용을 먼저 `git diff -- <경로>` 로 보여 주고, 사라진다는 점을 분명히 알린다.
3. **이미 저장(커밋)한 것** — 히스토리를 지우지 않고 반대 변경을 새 커밋으로 만든다: `git revert --no-edit <해시>`. 푸시는 하지 않는다(사용자가 원하면 `/ka-save 푸시`).
4. **여러 파일·불확실한 경우** — 무엇이 사라지는지 목록으로 보여 주고 사용자에게 어느 것을 되돌릴지 고르게 한다.

절대 하지 않는 것: `git reset --hard`, `git clean -f`, `git checkout -- .`, `git restore .`, force-push, 히스토리 재작성, 사용자가 만든 다른 미커밋 작업을 지우는 일. 훅이 막거나 확인창을 띄운다. 조사 원본 데이터(`.gpkg`/`.qgz`)는 어떤 경우에도 되돌림 대상이 아니다.

끝나면 무엇이 원래대로 돌아갔는지, 남은 변경이 무엇인지 결론 먼저 보고한다.
