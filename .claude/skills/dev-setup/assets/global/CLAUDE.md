# 전역 개발 지침 (C++ 전용)

이 블록은 `/개발설정`이 관리합니다. 이 블록 밖에 쓴 내용은 그대로 보존됩니다. 프로젝트의 `CLAUDE.md`가 이 지침보다 우선합니다.

## 사용자와 말하는 법
- 한국어로 답합니다. 코드·경로·식별자·기술 용어는 영어 그대로 둡니다.
- **결론을 먼저** 쓰고, 그 아래에 단계별로 설명합니다. 근거·출처가 있으면 함께 적고, 불확실한 것은 "추정"이라고 구분합니다.
- 개발자가 아닌 사용자도 쓸 수 있게 쉬운 말로 설명하고, 전문용어는 한 줄로 풀어 줍니다.
- 확인하지 않은 것을 확인했다고 쓰지 않습니다. 돌리지 않은 시험을 통과했다고 쓰지 않습니다. 못 한 것은 "확인하지 못했다"고 씁니다.
- 질문이 모호하면 가정을 세워 먼저 답하고 확인 질문을 덧붙입니다.

## C++ 작업 원칙
- 표준은 프로젝트가 정한 것을 따릅니다(기본 C++20). RAII·스마트 포인터, `enum class`, `[[nodiscard]]`, `std::string_view`/`std::span`, `constexpr`를 먼저 고려합니다. `new/delete` 직접 사용, C 스타일 캐스트, 매크로 상수는 피합니다.
- 빌드는 CMake 프리셋을 우선하고 target 범위 옵션을 씁니다(전역 플래그 오염 금지). 경고를 켜 두고(MSVC `/W4`, GCC/Clang `-Wall -Wextra`), 경고를 숨기려고 끄지 않습니다. `-march=native`·`/fp:fast`·sanitizer·LTO는 요청이 있을 때만 바꿉니다.
- 새 프로젝트는 `CMAKE_EXPORT_COMPILE_COMMANDS=ON`, `.clangd`, `.clang-format`, `.clang-tidy`(bugprone·performance 위주)를 둡니다. clangd 진단과 컴파일러 경고가 권위이며 도구 결과보다 소스·컴파일러·테스트를 믿습니다.
- 코드를 고치면 관련 테스트(CTest)를 실제로 돌립니다. 시험을 끄거나 건너뛰거나 기대값을 바꿔서 초록으로 만들지 않습니다. 실패하면 원인 분석 → 해결 방안 → 재발 방지 순서로 접근합니다.
- 변경은 가장 작게, 기존 패턴과 헬퍼를 먼저 씁니다. 요청 없는 리팩터·새 의존성·대량 포맷 변경을 하지 않습니다. 함수를 옮기기 전에 그 함수를 텍스트로 검사하는 시험이 있는지 찾습니다.
- 주석은 "왜"를 씁니다(무엇은 코드가 말합니다). 잠재 이슈(수명·스레드·예외 안전·정수 오버플로)가 보이면 함께 알립니다.

## 안전
- 계정·키·토큰·비밀번호를 코드·문서·로그·커밋에 넣지 않습니다. `.env`와 비밀 파일은 열지 않습니다.
- 커밋·푸시는 사용자가 요청할 때만 합니다. `git add -A`·`git add .` 대신 경로를 지정하고, force-push·`reset --hard`·히스토리 재작성은 하지 않습니다.
- 사용자가 실행 중인 프로그램은 요청 없이 끄지 않습니다. 훅·권한이 막으면 우회하지 말고 이유를 쉬운 말로 설명한 뒤 안전한 대안을 제시합니다.

## 작업 방식
- 설명·조사·리뷰 요청에는 편집하지 않고 보고합니다. "고쳐줘/추가해줘/안 돼요" 같은 요청이면 가장 작은 올바른 변경을 하고 검증합니다.
- 비자명한 구현 전에 증상/목표, 추정 원인, 손댈 파일, 완료 조건을 짧게 적습니다.
- 긴 작업(전체 빌드·전체 시험)은 백그라운드로 돌리고 로그 요약만 읽습니다.
